# Baudloom 验证计划

## 已有自动化覆盖

0.1.5 开发版覆盖 65 项核心测试及 Linux Electron 桌面/打包后测试。Windows CI 结果以 [Actions](https://github.com/Oniums/baudloom/actions) 为准。

- 串口参数完整传递、硬件流控不手动设置 RTS、无效参数拒绝和握手线设置失败关闭端口。
- 配置持久化、应用不连接或发送；设备消失保留原选择，重新出现不自动续连。
- TXT/LOG 编码、尾部预算、不修改原文件、无效文件保持已有视图和不伪造接收时间。
- 向上滚动暂停跟随与新增计数、标记跳转、单调时间差和无时间文本的明确提示。
- 发送区在 760 × 560 窗口下不出现内部滚动条，低频选项移入对话框。
- 自动换段的连续序号、从中间段重开、缺段、同名文件拒绝覆盖及实时导出边界。
- TXT/LOG 导出的 UTF-8/CRLF 连续解码、大量换行、缓存/筛选范围、元数据、取消与损坏时保留目标。
- 多词字面匹配、大小写、排除词、高亮与前后导航、保留上下文；桌面文件对话框取消与连接中完整导出。
- 自定义波特率、预设选择、非法值阻止连接、已连接禁用、成功值重载恢复。
- 增量视图与全量逐行一致：部分行补全、CRLF、缓存淘汰/缩小、格式切换、停止与重连；50000 行时空闲无日志行、新增一行只传尾部。
- 原始字节、分块 UTF-8/CRLF、未终止片段、非法 HEX、格式无损转换和校验向量。
- 发送目标、连接身份、定时顺序、取消、慢写不并发、故障后不续发。
- 队列/容量限制、短写、写盘与同步错误、打开/关闭竞态、损坏/截断历史。
- 默认不保存、连接中补写、创建期间 RX、原时间保留、缓存淘汰、启用失败、定时任务延续且不重放命令。
- 便携存储路径、完整设备名称、未连接编辑、命令恢复、会话只读重开。
- 接收列显隐与列宽、字号、缓存预算、上下分隔拖拽、设置持久化和 760 × 560 布局。
- 50000 行虚拟列表的首尾浏览与整个缓存搜索，实际挂载日志行少于 200。
- 50000 行关闭换行后的横向范围、首尾切换、表头水平同步、恢复换行；换行偏好刷新后保留。
- 760px / 1280px 接收操作菜单、Escape/点击外部关闭；设置弹窗、保存详情及未连接发送原因。
- 两个常驻区域，多条对话框不改变接收区大小；设置关闭后仍可直接停止定时。匹配关键词、排除高级条件、Ctrl+F，以及关闭/Escape 恢复未筛选视图。

## 实体设备与故障矩阵

下面项目待在具体设备与平台执行，记录版本、系统、CPU/内存、存储介质、适配器、驱动、波特率、持续时间及输入来源。

| 场景 | 验收证据 |
|---|---|
| Windows 虚拟串口 | 完整连接、双向字节、正常断开与记录重开 |
| USB 串口兼容 | 端口占用、拔插、COM 编号变化、完整名称、错误反馈 |
| 连续接收期间操作 | 暂停、清屏、筛选、列调整和布局拖动不改变保存的原始字节 |
| 保存与补写 | 未保存缓存→启用保存→继续接收，逐字节核对边界、原始时间与淘汰缺口 |
| 异常退出与恢复 | 缺少 stop、截断及损坏中间记录，保留来源，不伪造完整性 |
| 磁盘故障 | 慢盘、空间耗尽、权限变化，故障与未保存范围可见、自动发送停止 |
| 时钟与休眠 | 校时、时区变化、休眠，区分 UTC 与进程单调时钟边界 |
| 输入与显示 | 中文输入法、键盘、100/150/200% 缩放、长行与控制字节 |
| 便携与升级 | 只携带 EXE 启动，数据位置明确，已有数据不被覆盖或静默迁移 |

## 性能验收候选

基准候选为 Windows 11 x64、4 核以上 CPU、16 GiB 内存和本地 SSD；正式测量锁定具体型号。以下是待验证目标，不是当前性能承诺。

| 场景 | 测量方式 |
|---|---|
| 单路 115200 连续 8 小时 | 固定序号/校验输入，逐字节或序号核对缺口；包含多次自动换段，逐段核对边界 |
| 单路 921600 连续 1 小时 | 在适配器支持条件下记录有效吞吐、CPU、内存峰值和丢失范围 |
| 启动 | 同机比较 0.1.3/当前候选版 单 EXE 的首次/再次启动，各至少 10 次，记录点击到窗口可交互 p50/p95、杀毒状态、包大小与 TEMP 写入量；不能用 Linux 目录包启动代替 |
| 自定义速率 | 在适配器支持条件下验证 230400、460800、1000000 和非预设速率；不支持时明确报错，不能静默切换 |
| UI 操作 | 连续采集时测量搜索、调整、发送反馈的 p95 延迟 |
| 缓存预算 | 各档预算和长短行/UTF-8/HEX 组合，测量核心、界面与总进程工作集，校准内存提示模型 |

后续功能的验收随[产品范围](baudloom-product-requirements.md)扩展。没有输入和实测记录时，不将构建成功或短时自动化等同于整项通过。

## 0.1.5 本地基准记录（2026-11-03）

以下基准记录于本轮双区域界面改动前，不作为新布局的性能测量。环境：Linux、Intel i7-8550U、Electron 45.2.1，使用 Xvfb；测试数据均为合成。以下为单轮测量，不代表 Windows 单 EXE 冷启动或实体串口验收。

- 源码启动到连接按钮可用，10 次：p50 583 ms、p95 1108 ms，包含自动化启动开销。
- 50000 行缓存查找，40 次：p50 16.8 ms、p95 24.9 ms，包含自动化输入与断言开销。
- 核心持续接收并写盘 60 秒：输入与验证落盘均为 6372000 字节，保留 50000 行，写入队列峰值 14795 字节，事件循环 p95 11.84 ms。
- 核心进程 RSS 由约 86 MiB 增至约 197 MiB，包含缓存填满与文件验证。60 秒不足以判定长期内存稳定；桌面工作集和核心 RSS 也不是同一测量口径。

复现：`npm run benchmark`、`npm run benchmark:desktop`、`npm run benchmark:soak`。桌面基准支持 `BAUDLOOM_EXECUTABLE` 指向目录包可执行文件和 `BAUDLOOM_BENCH_TRIALS` 设置次数；持续测试支持 `BAUDLOOM_BENCH_SECONDS`（1–28800 秒，默认 60），在临时目录写入合成会话并清理，不连接硬件。持续测试按固定软件节奏注入，不模拟真实 UART 线速与驱动调度。

Windows 单 EXE 首次/再次启动、高 DPI、真实拔插以及 1–8 小时稳定性仍待实机验证；未因 Linux 测试通过而标记完成。

同机目录包补充测量（各启动 10 次、搜索 40 次）：0.1.4 启动 p50/p95 为 593/1103 ms，搜索 15.9/20.3 ms；0.1.5 启动 489/610 ms，搜索 16.3/21.5 ms。运行顺序、文件缓存和后台负载未严格隔离，这组数据只作回归参考，不能归因为确定的启动加速比例。
