# Baudloom 验证计划

## 已有自动化覆盖

0.1.3覆盖 49 项核心测试及 Linux Electron 桌面/打包后测试。Windows CI 结果以 [Actions](https://github.com/Oniums/baudloom/actions) 为准。

- 自定义波特率、预设选择、非法值阻止连接、已连接禁用、成功值重载恢复。
- 增量视图与全量逐行一致：部分行补全、CRLF、缓存淘汰/缩小、格式切换、停止与重连；50000 行时空闲无日志行、新增一行只传尾部。
- 原始字节、分块 UTF-8/CRLF、未终止片段、非法 HEX、格式无损转换和校验向量。
- 发送目标、连接身份、定时顺序、取消、慢写不并发、故障后不续发。
- 队列/容量限制、短写、写盘与同步错误、打开/关闭竞态、损坏/截断历史。
- 默认不保存、连接中补写、创建期间 RX、原时间保留、缓存淘汰、启用失败、定时任务延续且不重放命令。
- 便携存储路径、完整设备名称、未连接编辑、命令恢复、会话只读重开。
- 接收列显隐与列宽、字号、缓存预算、三窗交汇拖拽、设置持久化和 760 × 560 布局。
- 50000 行虚拟列表的首尾浏览与整个缓存搜索，实际挂载日志行少于 200。

测试使用合成设备、SerialPort MockBinding 和临时文件。构建与这些测试不能证明 Windows 真实驱动兼容、持续吞吐或长期内存稳定。运行命令见[开发指南](baudloom-development-guide.md)。

## 实体设备与故障矩阵

下面项目待在具体设备与平台执行，记录版本、系统、CPU/内存、存储介质、适配器、驱动、波特率、持续时间及输入来源。

| 场景 | 验收证据 |
|---|---|
| Windows 虚拟串口 | 完整连接、双向字节、正常断开与记录重开 |
| USB 串口兼容 | 端口占用、拔插、COM 编号变化、完整名称、错误反馈 |
| 连续接收期间操作 | 暂停、清屏、筛选、列调整和布局拖动不改变保存的原始字节 |
| 保存与补写 | 未保存缓存→启用保存→继续接收，逐字节核对边界、原始时间与淘汰缺口 |
| 异常退出与恢复 | 缺少 stop、截断及损坏中间记录，保留来源，不伪造完整性 |
| 磁盘故障 | 慢盘、空间耗尽、权限变化，故障与未保存范围可见、自动发送停止 |
| 时钟与休眠 | 校时、时区变化、休眠，区分 UTC 与进程单调时钟边界 |
| 输入与显示 | 中文输入法、键盘、100/150/200% 缩放、长行与控制字节 |
| 便携与升级 | 只携带 EXE 启动，数据位置明确，已有数据不被覆盖或静默迁移 |

## 性能验收候选

基准候选为 Windows 11 x64、4 核以上 CPU、16 GiB 内存和本地 SSD；正式测量锁定具体型号。以下是待验证目标，不是当前性能承诺。

| 场景 | 测量方式 |
|---|---|
| 单路 115200 连续 8 小时 | 固定序号/校验输入，逐字节或序号核对缺口；记录文件上限需先扩展为分段记录 |
| 单路 921600 连续 1 小时 | 在适配器支持条件下记录有效吞吐、CPU、内存峰值和丢失范围 |
| 启动 | 同机比较 0.1.2/0.1.3 单 EXE 的首次/再次启动，各至少 10 次，记录点击到窗口可交互 p50/p95、杀毒状态、包大小与 TEMP 写入量；不能用 Linux 目录包启动代替 |
| 自定义速率 | 在适配器支持条件下验证 230400、460800、1000000 和非预设速率；不支持时明确报错，不能静默切换 |
| UI 操作 | 连续采集时测量搜索、调整、发送反馈的 p95 延迟 |
| 缓存预算 | 各档预算和长短行/UTF-8/HEX 组合，测量核心、界面与总进程工作集，校准内存提示模型 |

后续功能的验收随[产品范围](baudloom-product-requirements.md)扩展。没有输入和实测记录时，不将构建成功或短时自动化等同于整项通过。
