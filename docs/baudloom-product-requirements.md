# 串口调试工作台产品需求

> 状态：草稿，产品方向已认可，细节尚待原型验证
> 适用范围：Baudloom 桌面应用首版及后续版本规划
> 更新日期：2026-11-02

## 1. 定位与成功标准

首批用户是需要反复观察重启、长时间运行、发送调试命令和复盘异常的 MCU/IoT 工程师。首版优先验收 Windows 桌面使用；跨平台能力保留在架构中，不提前宣称已支持。

核心体验：插入设备后迅速看到日志；测试期间自动保留过程；测试结束后能找到关键事件、回看命令与响应，并导出有上下文的材料。

产品默认离线可用，不要求账号、不上传日志、不依赖 AI。默认使用中文界面，布局与数据格式为后续英文界面保留空间。

首版价值由三项任务验证：第一次连接、整夜采集、异常复盘。具体标准见[验收计划](baudloom-mvp-test-plan.md)。

## 2. 典型使用流程

### 2.1 快速连接

1. 启动后展示可用设备名称、端口号及可识别的 USB 信息。
2. 选择设备和波特率，查看数据位、校验、停止位、流控及 DTR/RTS 配置。
3. 点击连接，自动创建会话并开始本地记录，无需先建项目。
4. 日志区显示数据；状态栏显示记录目录和写入状态。

首次使用显示默认保存路径，允许更改；后续沿用设置。记录目录不可写时不得悄悄退化为“看起来正在记录”的模式：连接前提示，用户可以修复目录，或显式选择仅监视。

串口默认参数为 115200、8N1、无流控；设备配置保存后优先使用该设备设置。编码默认 UTF-8，可选 GB18030 和 HEX。原始字节不因编码选择而改变。

### 2.2 长时间测试

用户可命名会话、填入固件标识、按快捷键添加“开始测试”“手动断电”等书签。连接中断和重新连接自动记为事件。

暂停滚动后界面停留在当前阅读位置，同时显示后台新增数量；恢复跟随后跳至末尾。清屏仅建立新的视图起点，会话历史仍可查看。停止采集使用独立操作，避免与暂停滚动混淆。

关闭窗口时，在仍有采集任务的情况下提供“后台继续”和“停止并退出”。后台采集必须有托盘状态及停止入口；显式退出后不自行重启采集。

### 2.3 异常复盘

断开设备后仍能打开历史会话。用户搜索异常、展开前后上下文、从书签跳转、选中两条记录测量间隔。导出前展示范围、是否经过筛选和包含的设备。

历史 TXT/LOG 可以导入为离线会话；保留原文件，不推造原始字节、精确时间或设备版本。无法识别时间时按原文件顺序展示。

## 3. 首版范围

下列 P0 项构成可日用的第一版，开发顺序允许拆分，但缺少任一项时应标为预览版。

| ID | 功能 | P0 行为边界 |
|---|---|---|
| R01 | 连接与设备识别 | 枚举、别名、配置保存、明确的打开失败信息；不自动抢占端口 |
| R02 | 文本与 HEX 收发 | 编码、换行、发送预览、历史；无效 HEX 阻止发送并定位错误 |
| R03 | 多连接 | 至少两个独立端口并行；切换或双栏查看，发送目标始终可见 |
| R04 | 会话自动记录 | 原始字节、收发方向、连接事件、参数及人工标记；可见保存状态 |
| R05 | 有界缓存与故障报告 | 显示缓存与记录分开；磁盘失败、溢出、恢复缺口可见 |
| R06 | 断线重连 | 仅匹配已选设备；歧义时等待选择；不补发历史命令 |
| R07 | 日志阅读 | 暂停滚动、搜索、大小写开关、包含/排除筛选、上下文、关键词高亮 |
| R08 | 书签与时间差 | 手工书签、备注、定位、同一有效时钟域内的间隔计算 |
| R09 | 常用命令组 | 名称、内容、编码、换行、导入导出；定时发送可随时停止 |
| R10 | 离线历史与导出 | 会话重开、TXT/LOG 导入、文本和结构化导出、原始 RX 字节导出 |
| R11 | 桌面生命周期 | 后台采集、明确退出、异常结束后恢复检查 |
| R12 | 键盘与显示 | 高 DPI、字体大小、浅深主题、键盘可达、焦点状态明确 |

文本搜索首先提供字面匹配；正则搜索进入 P1，届时必须有资源限制。串口握手线是 P0 配置；BREAK、自动校验和文件传输放入 P1。P0 不实现完整终端仿真，控制字节可查看，不执行终端控制脚本。

默认右侧详情折叠，给日志更多宽度。设备栏在单连接时可以收起。连接中断、记录异常同时使用文字和图标，不能只依赖颜色。

基础快捷键：Ctrl+F 搜索、Ctrl+Enter 发送、Ctrl+B 给当前记录加书签。发送区 Enter 默认换行；避免全局 Enter 触发设备操作。快捷键可调整，不覆盖输入法正常输入。

## 5. 必须明确的交互语义

| 操作或状态 | 定义 |
|---|---|
| 暂停滚动 | 保留阅读位置，采集和记录继续 |
| 清屏 | 清除当前视图，保留会话；提供查看此前记录的入口 |
| 筛选/折叠 | 仅改变显示，不修改原始记录 |
| 停止记录 | 与停止采集分开，持续显示“仅监视，未记录” |
| 断开 | 主动关闭该端口并取消自动重连；定时发送停止 |
| 意外断开 | 可等待同一设备重连；定时发送停止，重连后需重新启动 |
| 发送成功 | 仅表明主机写入结果；设备响应和业务成功另行判断 |
| 自动识别到重启 | 作为规则生成的事件，显示规则来源，不能当作硬件复位事实 |
| 导出当前视图 | 明示筛选条件和范围；与完整会话导出分开 |
| 删除会话 | 明确列出文件范围后确认；清屏不承担删除功能 |

记录发生故障时，醒目显示“记录已中断”，停止周期发送和自动操作。允许用户继续手工监视和发送，但不能把这段时间描述为完整记录。恢复记录需新增恢复事件，不静默覆盖故障状态。

多连接情况下，发送草稿与设备绑定；切换目标后不能把上一台设备的待发送内容自动发给新目标。连接丢失时取消未执行队列，部分写入显示实际结果及不确定性。

## 6. 后续版本

| 阶段 | 内容 | 进入条件 |
|---|---|---|
| P1 复现排障 | 多设备合并时间线、成功/失败对齐、事件规则、命令步骤与等待响应、正则、校验、基础曲线 | P0 采集和恢复验收通过 |
| P2 扩展协作 | 本地 API/CLI、AI 分析接入、远程采集、可隔离的协议解析扩展 | 会话格式稳定、访问与发送权限明确 |

P0 可导出带上下文的文本供外部分析；AI 不进入采集链路。后续 AI 的结论应引用原始记录，推测与观测分开，向外部服务上传前展示范围与脱敏结果。

首版不做云账号、插件市场、完整协议大全、完整终端仿真或固件烧录。OTA 是可观察的调试场景，不代表本工具承担特定产品的升级协议实现。

## 7. 命名、开源和样例

正式项目名称为 **Baudloom**，目录与仓库短名使用 `baudloom`，于 2026-11-02 确定。项目采用独立代码和素材，不包装原版 SSCOM，也不暗示官方关系。此前公开网页与 GitHub 检索未发现明确同名软件；这不代表全球唯一，域名、包名和正式商标检索尚未核验。MIT 是原创代码许可证候选，最终选择要结合依赖和素材授权，当前不作法律结论。

公开样例全部使用合成数据。设备密钥、配网信息、公司固件日志和内部命令集不进入默认样例。用户自定义配置留在本地；导出配置前可预览内容。

## 8. 实施顺序

1. 用合成事件做界面交互原型，检查快速连接、日志阅读、发送目标与故障状态。
2. 实现最小采集和记录链路，验证恢复格式；对候选 UI 与核心接口进行小规模技术验证。
3. 接入单串口，再完成双串口、重连、命令组和离线阅读。
4. 执行首版验收矩阵，根据测量结果收敛缓存和性能预算。
5. 整理 Windows 包、使用文档、依赖授权和发布材料，再单独执行获授权的 GitHub 发布。

界面演示、模拟测试和真实 Windows 串口验收分别报告。当前处于设计阶段，不代表上述步骤已完成。
