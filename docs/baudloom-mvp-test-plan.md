# 串口调试工作台首版验收计划

> 状态：草稿，所有测试均未执行
> 适用范围：Baudloom Windows 首版
> 更新日期：2026-11-02

验收对应[产品需求](baudloom-product-requirements.md)与[核心架构候选](baudloom-core-brainstorm.md)。本文所有数值是暂定验收预算，不代表已实现能力。

## 1. 测试分层

| 层级 | 可以证明 | 不能替代 |
|---|---|---|
| 合成数据交互原型 | 布局、操作语义、状态可理解性 | 实际收发、性能、恢复 |
| 主机模拟与故障注入 | 编码、队列、格式、截断、索引重建等实现行为 | Windows 驱动和真实 USB 故障 |
| Windows 虚拟串口 | Windows 应用集成与收发流程 | 实体适配器、电气错误、握手线波形 |
| Windows 实体设备 | 指定版本、适配器、负载下的实测结果 | 所有硬件兼容性、业务协议最终成功 |

所有发布结论写明软件版本、系统版本、CPU/内存、存储介质、适配器及驱动、波特率、测试时间和数据来源。虚拟设备与实体设备报告分开。

## 2. 功能与故障矩阵

| ID | 对应需求 | 场景 | 通过条件 |
|---|---|---|---|
| T01 | R01、R04 | 全新配置首次连接 | 不建工程即可收日志；目录可见且实际可写；基础信息完整 |
| T02 | R01 | 端口被占用、拔掉或权限不足 | 报告失败原因和目标，不误报连接成功，不强占设备 |
| T03 | R02 | 文本/HEX、CR/LF/CRLF/无换行 | 合成接收端逐字节核对发送预览；非法 HEX 不产生写入 |
| T04 | R02、R04 | UTF-8/GB18030 字符、CRLF 被切成任意读取块 | 解码稳定；原始字节逐字节一致；断线残片不拼入下一连接 |
| T05 | R03 | 两个端口并行，切换目标和草稿 | 采集互不混淆；发送目标始终正确且明确 |
| T06 | R04、R07 | 暂停滚动、清屏、筛选和切换主题期间持续输入 | 与基准输入对比，持久记录不受显示操作影响 |
| T07 | R06、R09 | 拔插 100 次、COM 编号变化、两个同型号设备 | 不误连/误发；连接段与故障可追踪；定时发送不自行恢复 |
| T08 | R05、R11 | 强制结束 UI 与核心，分别重复 100 次 | UI 结束不破坏核心采集；核心结束后报告可验证恢复边界，不改写原文件 |
| T09 | R05 | 截断末尾、破坏中间记录、丢失索引、损坏 manifest | 不越界分配；保留来源；标注缺口；必要身份和可验证记录可恢复 |
| T10 | R05 | 慢盘、空间耗尽、目录失去写权限 | 记录故障明确；自动发送停止；内存有上限；未保存范围不被伪装为已保存 |
| T11 | R08 | 校时、时区变化、休眠、核心重启 | 有效单调时间段内间隔正确；跨未知边界不显示伪精确结果 |
| T12 | R09 | 定时发送遇到延迟、部分写入和断线 | 不并发堆积、不补发遗漏周期；写入结果与设备响应分开 |
| T13 | R10 | TXT/LOG 导入与所有导出模式 | 原文件不变；缺失信息明确；过滤导出与完整导出可区分 |
| T14 | R11 | 关闭窗口、后台继续、托盘停止、正常退出 | 行为符合选择；停止过程收尾状态可见；不遗留失控采集 |
| T15 | R12 | 中文输入、键盘操作、100/150/200% 缩放 | 不误发送、控件可达、日志不重叠、焦点可见 |
| T16 | R01 | DTR/RTS 和硬件流控组合 | 配置与实测相符；报告驱动/硬件限制；不宣称未经测量的无复位保证 |
| T17 | R05、R07 | 极长无换行输入、NUL、控制字节、超长单行 | 内存有界、可显示片段、原始记录可追溯；不执行终端或系统指令 |

## 3. 暂定性能预算

基准候选为 Windows 11 x64、4 核以上 CPU、16 GiB 内存、本地 SSD；正式测试锁定具体型号。Windows 10 与 ARM64 暂不纳入首版已验证支持列表。

| 场景 | 输入与持续时间 | 暂定目标 |
|---|---|---|
| 日常双设备采集 | 两路 115200、8N1，连续 12 小时 | 具有序号与校验的测试流完整核对；无无法解释的缺口 |
| 高速单设备 | 一路 921600、8N1，连续 1 小时 | 在适配器支持条件下逐字节或序号核对，记录实际有效吞吐 |
| UI 响应 | 在上述采集期间搜索、切换设备、加书签 | 常用操作反馈 p95 ≤ 200 ms；首次全文件搜索允许显示可取消进度 |
| 资源稳定 | 双设备 12 小时 | UI 与核心合计工作集目标 ≤ 512 MiB，稳定阶段不随总日志量持续增长 |
| 离线大文件 | 1 GiB 合成文本日志 | 首屏 ≤ 3 秒；完整搜索 ≤ 15 秒；不要求一次载入全部文件 |
| 恢复 | 1 GiB 会话，尾段截断且索引需重建 | 可验证首段可阅读 ≤ 5 秒；完整重建 ≤ 60 秒；始终标注恢复状态 |

性能目标如不可达，记录测量和瓶颈，再修改产品预算，不把未测数字变成宣传承诺。虚拟输入速度不等于物理串口吞吐。8N1 的有效字节上限受起止位影响，按实际收到的字节计算吞吐。

## 4. 数据与证明方法

模拟流使用固定种子生成序号、时间字段和校验，同时覆盖多语言文本、随机二进制、控制字节和长行。接收侧与生成侧独立核对，不仅检查 UI 行数。

故障注入保留原始会话副本；记录注入时机、最后成功同步点、恢复终点、缺口和未知范围。断电恢复需单列实机实验，不能由强杀进程测试替代。

握手线波形验证使用专门测试板和测量设备，不在业务 DUT 上默认执行可能导致复位的操作。开源仓库使用合成样例和可复现测试工具，真实业务日志单独保管。
