# Baudloom 开发与架构

## 工程结构

- `src/renderer`：纯 DOM 界面、发送工具、虚拟日志列表和布局设置。
- `src/desktop`：Electron 主进程、preload、存储路径、文件对话框和生命周期。
- `src/core`：独立 utility process 中的串口、发送调度、缓存、记录和历史读取。
- `src/shared.ts`、`src/snapshot.ts`、`src/baud-rate.ts`、`src/send-tools.ts`、`src/view-settings.ts`：接口、共用字节规则与缓存预算。
- `tests`：核心行为测试及 Electron 桌面测试。
- `assets/brand`：原创图标源稿及生成结果。

渲染器启用 context isolation 和 sandbox，关闭 Node integration；仅通过固定 preload 接口调用主进程。IPC 校验来源，页面不加载远程内容。每个串口标签页使用独立 WebContentsView 和采集进程，IPC 按来源标签页路由；刷新不关闭连接，但会取消定时发送。

## 构建与测试

```sh
npm ci
npm run icons
npm run format:check
npm run typecheck
npm test
npm run test:desktop
npm run benchmark
npm run benchmark:desktop
npm run benchmark:soak
npm run package:win
```

Windows 单文件输出为 `artifacts/Baudloom.exe`（内部版本仍随发布更新）。`artifacts/Baudloom-win32-x64` 为打包中间结果；Linux 验证包可使用 `npm run package:linux`。

打包后测试用 `BAUDLOOM_EXECUTABLE` 指定应用可执行文件。Linux 无桌面环境需要 Xvfb 和 Electron 系统依赖。root 测试环境的 `--no-sandbox` 仅由测试启动器添加，产品入口不添加。

`package-lock.json` 固定依赖。GitHub Actions 在 Windows 上执行格式、类型、核心、桌面和打包后验证；每次运行结果见 Actions，不能用配置存在推断运行通过。

## 启动与刷新

从 0.1.3 起使用 ASAR 合并应用文件，`.node` 原生绑定保留为实际文件；Electron 只保留 `zh-CN` 和 `en-US` 语言资源。便携包启用 `useZip`，使用 NSIS 内置 zlib 直接解包，避免先提取 7z、再解压、再复制的路径；每次启动分配独立 TEMP 目录，退出清理。本方案仍需每次解包，包体积比 0.1.2 大。参考 [Electron ASAR](https://www.electronjs.org/docs/latest/tutorial/asar-archives) 与 [portable 配置](https://www.electron.build/docs/api/app-builder-lib.interface.portableoptions/)。

启动时读取会话目录偏好，每个新标签页用当前默认目录启动自己的采集进程。初始视图、设备枚举和目录显示分别加载，枚举慢时不阻挡首个视图。

`snapshot` 不带游标时返回完整视图；界面轮询携带会话、格式、最后行号和修订号，返回新增/变化尾部以及首行号、总缓存行数。未终止片段使用原行号替换，缓存淘汰同步删除头部；格式切换或会话变化自动返回全量。游标只影响显示传输，不影响原始事件。界面丢弃过期格式/视图请求，空闲时复用行数组。连接状态轮询间隔为上次请求完成后 100 ms，未连接或后台为 1000 ms，不并发积压。

显示和原始缓存使用带游标的队列，移除头部时释放引用，定期压缩，避免每条记录调用数组头部删除。发送上下文未变化时跳过校验预览重算，日志时间格式器复用。

`npm run benchmark` 使用合成数据报告核心处理时间、50000 行缓存下完整/空闲/新增一行快照的 JSON 字节量。它不打开硬件或保存会话，JSON 字节量用于比较数据规模，不等于 Electron IPC 的精确编码大小。

## 数据与存储语义

默认根目录为原始便携启动器目录下的 `Baudloom-data`。`PORTABLE_EXECUTABLE_DIR` 用于定位原始 EXE，目录包使用其可执行文件目录，开发模式使用项目根目录。测试可通过 `BAUDLOOM_DATA_DIR` 指向临时目录。不可写时明确报错，不静默改存其他路径。

原始事件使用 JSONL：版本、文件会话 ID、序号、UTC、单调时钟、来源、端口、波特率及事件数据。RX/TX 字节为 base64，单条 SHA-256 用于发现意外损坏，不提供身份认证。

| 项目 | 当前边界 |
|---|---|
| 文件写入与扫描 | 每段 64 MiB 自动换段；没有全历史分页 |
| 实时写入队列 | 4 MiB，超限停止采集并报告 |
| 补写队列 | 32 MiB，与实时队列分别计量 |
| 显示缓存 | 文本/HEX 各自默认 10000 行 / 4 Mi 字符，任一超限淘汰 |
| 原始缓存 | 事件数按行数预算，序列化字节容量按字符预算；最大 50000 个事件 / 16 MiB |
| 历史读取 | 扫描同组全部分段，按当前预算保留尾部事件；缺段或损坏时保留已验证前缀 |
| 同步 | 连接、补写完成、周期和正常退出请求同步；不保证断电零丢失 |

连接中开始保存时，先在发送串行队列中等待当前发送完成；文件创建期间继续缓存 RX。缓存事件同步排入写入队列后切换新事件目标，保留原 at/mono、原始字节和请求关联。文件 start 表示创建时刻，后面的补写事件时间可能更早；文件顺序由 seq 定义。连接身份独立于文件 UUID，补写不改变发送目标或重放命令。补写成功同步后才显示完成数量；创建失败不关闭原有未保存连接，接管后的写盘错误会停止采集。

缓存事件与显示行不一一对应。视图设置的内存提示是容量模型：`6 × 字符容量 + 256 × 行数` 至 `16 × 字符容量 + 1024 × 行数`，换算 MiB，包含原始缓存、两种视图、IPC 副本及界面对象。它不是实测值或硬上限，不含 Electron 基础内存。

## 分段、查找与导出

首段沿用 `<时间>-<UUID>.baudloom.jsonl`，后续为同一前缀加 `.part000002`、`.part000003`。同一写入队列内同步并关闭前段，再以独占创建方式打开下一段；文件会话 ID 与事件序号连续，只在首尾记录 start/stop。换段失败沿用写盘故障处理，不覆盖同名文件。单个事件不跨文件拆分。

打开任一段只发现同目录同前缀文件，检查段号、事件序号、校验和收尾。搬移会话需要保留全部分段及原名。读取逐块进行，尾部缓存有容量限制；搜索不访问已经淘汰的历史。多词使用字面 `|` 分隔，最多 6 个、每个最多 80 字符，转义后匹配，显示用文本节点与 mark 元素，日志不能注入 HTML。

TXT/LOG 导出先写目标目录的临时文件，同步完成后替换目标；取消、缺段、损坏及写入失败时移除临时文件，保留原目标。强制终止进程可能留下临时文件，不保证断电事务性。格式采用 UTF-8、可选 UTC 时间和方向以制表符分隔；选中文字按原样输出。

缓存导出包含确认时尚未淘汰的全部缓存；筛选导出应用打开对话框时的筛选、格式和清屏边界。两者不等于整个磁盘会话。完整会话导出在采集进程中逐段扫描并使用有界解码器，重建跨事件 UTF-8/CRLF；不受窗口缓存上限影响。连接中先在写入队列插入同步屏障，固定每段完整记录的字节边界，后续采集继续，导出仅读取该边界。每次只允许一个导出任务。

## 连接配置与阅读

串口配置在主机采集入口验证，默认仍为 8N1。RTS/CTS 模式完全跳过手动握手线设置；其余模式在 open 回调后设置 DTR/RTS，失败时关闭句柄。连接参数随原始事件保存。旧会话缺少新字段仍可读取。设置修改需要断开，不隐式重连。

端口枚举采用独立的两秒轮询，同一时间仅一个请求；结果不变时不重建选择器。设备消失保留缺失项及发送草稿，不跳到列表中的另一设备；枚举失败不据此关闭正在连接的句柄。真实断线仍由 transport 的错误/关闭事件停止采集和定时发送。

命名配置存于同级 profile 目录中的本地页面存储，最多 20 组，显式保存/覆盖/删除；包括连接参数、发送草稿和多条命令，不包含打开连接或启动定时器的动作。应用前验证，复制后填入控件，不共享可变对象。发送历史不随配置替换。

普通 TXT/LOG 逐块解码 UTF-8 或 BOM 标识的 UTF-16，严格拒绝非法编码和 NUL。仅保留当前预算的尾部行，8192 字符长行分段，无接收时间/方向和原始会话事件；完整会话导出不适用于普通文本。读取失败不替换已有视图。

向上滚动冻结当前显示快照，采集继续；新增数量由实时总行号与冻结快照之差计算。回到最新使用当前缓存，可能已淘汰更早内容。标记导航限定为当前缓存，跳转时解除筛选和清屏边界。两行计时优先采用同会话单调时钟，缺少时回退 UTC 并明确提示；普通文本没有可信时间，不参与计时。

发送区固定为输入与常用操作，不设置面板滚动；输入框随分区伸缩，长内容可滚轮/键盘浏览但隐藏滚动条。末尾、历史、校验、定时和清空选项位于独立对话框；多条命令列在日志右侧，可调整宽度并记住展开状态。单条编辑栏沿用 bottom 高度偏好。专注模式收起两处发送区域，状态栏保留定时停止按钮。

接收流默认 14px，时间和方向作为可选的行内前缀。实时滚动只挂载视口附近的行，选择文本时将视口外的缓存分块补齐；关闭自动换行时按当前缓存测量横向范围。换行偏好保存在原视图设置中。所有宽度下，接收区次要操作均位于原生 popover；支持 Escape 和点击外部关闭。视图和连接参数使用模态对话框。查找由按钮或 Ctrl+F 展开，匹配关键词是主输入，排除词位于可展开的高级条件；关闭或 Escape 清除关键词与排除词后重新渲染，避免隐藏的筛选条件残留。

## 发送语义

UTF-8/HEX 转换只转换内容；无法无损转换的控制字节或非法编码不静默替换。校验覆盖从 1 开始、包含两端的字节范围，结束留空表示末尾；校验追加到整个内容后，再追加文本换行。

定时任务复制整批命令与目标，逐条写入完成后等待间隔，不并行积压或补发周期。停止、断线、故障、界面刷新及退出使未执行任务失效，已经交给串口的字节无法撤回。

## 发布流程

1. 更新版本、更新记录和当前限制，完成适用测试。
2. 核对提交只包含当前源码、测试、文档与原创资源；排除开发缓存、用户数据、旧原型和构建目录。
3. 打包并核对内嵌版本、许可证、原生依赖、图标和最终源码的一致性，计算 SHA-256。
4. 推送源码，检查 Windows CI；为确切提交创建 `v<版本>` 标签。
5. Release 附上 Windows EXE 和仅包含本次文件的 `SHA256SUMS`，注明验证范围与未完成的实体设备验收。
